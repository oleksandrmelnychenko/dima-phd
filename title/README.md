# LaTeX-проєкт дисертації

Тема: «Інформаційна технологія виявлення ознак аномального вмісту в мультимедійних даних вебсередовища».

## Основні файли

- `main.tex` - головний файл проєкту;
- `intro.tex`, `chapter_1.tex`-`chapter_4.tex`, `conclusions.tex` - дисертаційний текст;
- `references.bib`, `references.tex` - бібліографічна база і підключення списку джерел;
- `figures_drawio/` - окремі чорно-білі джерела draw.io;
- `figures_tex/` - відповідні векторні TikZ-вставки для збирання PDF;
- `source_map.md` - карта використаних джерел і меж доказової бази;
- `qa_report.md` - підсумок автоматизованої та візуальної перевірки;
- `manual_verification.md` - питання, що потребують авторської або інституційної перевірки.

Науковий каркас роботи утворюють модель мультимодального представлення прихованої загрози, метод аналізу спектральних, зорових і структурних ознак, метод поведінкового узгодження ознак різного походження та інформаційна технологія, організована у п’ять послідовних етапів.

## Стан готовності

- розділи 1-4 повністю переписано за затвердженою структурою;
- `_build/main.pdf` містить 210 сторінок формату A4;
- `denysiuk_thesis_review.docx` після фактичного оновлення полів і змісту має 222 сторінки в Microsoft Word; контрольний LibreOffice-рендер містить 221 сторінку через відмінності рушіїв верстки;
- текст від початку розділу 1 до завершення загальних висновків займає 154 сторінки (с. 34–187);
- робота містить 22 рисунки, 43 нумеровані таблиці, 36 нумерованих формул і два алгоритми;
- метод аналізу спектральних, зорових і структурних ознак займає 17 сторінок (с. 92–108), а метод поведінкового узгодження ознак різного походження --- 17 сторінок (с. 109–125);
- список використаних джерел містить 110 найменувань, усі цитування зосереджено в розділі 1;
- другий метод наскрізно подано як формалізований результат; скорочену модель узгодження статичних оцінок перевірено окремо, а кількісних властивостей повної причинно-подієвої конфігурації не заявлено;
- додаток містить завершені документальні матриці «новизна → публікація → сторінки → експеримент» і «публікація → особистий внесок → межа використання»;
- службові коди наукових результатів та текстові посилання на них вилучено;
- результати автоматизованої, змістової, формальної та візуальної перевірок задокументовано у `qa_report.md`.

## Відкриття проєкту без збирання PDF

Рекомендований редактор - **Visual Studio Code** із розширенням **LaTeX Workshop**.

1. Установіть Visual Studio Code.
2. За потреби встановіть розширення LaTeX Workshop. Для читання й редагування `.tex` воно не є обов’язковим.
3. Відкрийте файл `dissertation.code-workspace` через **File → Open Workspace from File**.
4. Головним файлом проєкту є `main.tex`. Текст розділів розміщено у `chapter_1.tex`-`chapter_4.tex`.

У робочому просторі автоматичне збирання LaTeX вимкнено. Збереження `.tex`-файлів не запускає створення або оновлення PDF.

Альтернативний редактор - **TeXstudio**. У ньому потрібно відкрити `main.tex` через **File → Open**. Збирання не запускається, доки користувач не виконає окрему команду Build.

## Збирання

**Windows.** У PowerShell із каталогу проєкту виконайте:

```powershell
.\build.ps1
```

**macOS / Linux.** У терміналі з того самого каталогу виконайте:

```bash
sh ./build.sh
```

Обидва сценарії визначають усі шляхи відносно свого розташування, збирають проєкт у `_build` і створюють `dissertation_reviewed.pdf` у поточному каталозі проєкту. Спочатку вони шукають виконуваний файл Tectonic у каталозі `_tools/tectonic` від кореня репозиторію, а потім — команду `tectonic` у системному `PATH`. Якщо компілятор не знайдено, під час першого запуску сценарій завантажує відповідний офіційний випуск до `_tools/tectonic`; для цього потрібне підключення до Інтернету. Наступні збирання використовують уже завантажений локальний файл.

За потреби назву готового файла можна змінити без зазначення шляху:

```powershell
.\build.ps1 -OutputName thesis.pdf
```

```bash
sh ./build.sh thesis.pdf
```

На Windows автоматичне завантаження підтримує архітектуру x64, для якої Tectonic публікує готовий виконуваний файл. На macOS і Linux вибір платформи та архітектури виконує офіційний інсталятор Tectonic. Якщо готового випуску для певної платформи немає, Tectonic потрібно встановити окремо й додати до `PATH`.

Нумерацію формул формує LaTeX за розділами. Нові рисунки потрібно додавати одночасно до `figures_drawio/` і `figures_tex/`.
