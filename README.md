# Дисертаційний проєкт

Репозиторій містить текст докторської дисертації «Інформаційна технологія виявлення ознак аномального вмісту в мультимедійних даних вебсередовища», матеріали для її перевірки та пам’ять погоджених рішень щодо наукового стилю, термінології й доказової межі.

## Структура репозиторію

- `title/` — основний LaTeX-проєкт дисертації, рисунки, бібліографія та сценарії збирання PDF;
- `memory/` — спільна пам’ять автора, рецензентів і Codex;
- `.agents/skills/` — проєктні навички для роботи з дисертацією та пам’яттю;
- `.codex/agents/` — налаштування допоміжних агентів;
- `suport_info/` — незмінні джерельні матеріали;
- `my/` — робочі документи, звіти та проміжні матеріали.

Усі шляхи в документації, пам’яті та звітах записують відносно кореня репозиторію.

## Як працювати з пам’яттю

Перед написанням, переписуванням або рецензуванням потрібно прочитати:

1. `AGENTS.md`;
2. `memory/README.md`;
3. `memory/MEMORY.md`.

У `memory/MEMORY.md` використовуються такі статуси:

- `Погоджено` — правило або редакцію схвалив автор;
- `Уникати` — підтверджений небажаний шаблон;
- `Контекстне` — правило діє лише в указаній сфері;
- `Очікує рішення` — пропозиція ще не є обов’язковою;
- `Замінено` — чинним є новіший пов’язаний запис.

Нові зауваження рецензента або моделі спочатку отримують статус `Очікує рішення`. Лише автор може погодити, відхилити або звузити їх. Пам’ять не замінює джерел, формул, експериментальних результатів та інституційних вимог.

## Редакційна межа

Завдання чату й допоміжних агентів полягає не у створенні нової науки, а в точному академічному описі вже наявного наукового змісту. Під час редагування дозволено покращувати мову, структуру викладу, термінологію, зв’язність і тлумачення наявних матеріалів без кардинальної зміни їхньої логіки.

Не можна вигадувати нові положення, гіпотези, механізми, моделі, методи, критерії, класифікації, результати, числа, експерименти, переваги чи наукову новизну. Якщо наявних матеріалів недостатньо для коректного твердження, потрібно зафіксувати прогалину й передати її автору, а не заповнювати припущенням.

Після зміни пам’яті потрібно виконати:

```powershell
python .agents/skills/dissertation-memory/scripts/validate_memory.py --root .
```

## Погоджений цикл редагування

1. Автор надає фрагмент або вказує місце, яке потрібно опрацювати.
2. Агент знаходить текст у `title/` і читає попередній, цільовий та наступний абзаци. Для змістової зміни аналізується весь підрозділ.
3. Перевіряються наукова коректність, доказова опора, сила тверджень, зв’язність, термінологія, англіцизми та відмінність між технічним описом і науковим висновком.
4. За доступності залучається незалежний агент `memory_auditor` у режимі лише читання. Він нічого не редагує.
5. Агент показує запропоновану редакцію та коротко пояснює змістові зміни й невирішені питання.
6. Файли дисертації не змінюються до явного підтвердження автора, наприклад `Ок, внось`.
7. Після рішення автора відповідний запис пам’яті оновлюється. Повторно застосовне правило додається лише в обґрунтованій сфері.
8. Погоджена редакція вноситься до `title/`, після чого перевіряються залежні терміни, формули, рисунки, таблиці, цитування та висновки.
9. Дисертація збирається у `title/dissertation_reviewed.pdf` і передається на наступне рецензування.
10. Нові зауваження рецензента проходять той самий цикл: запис у пам’яті, рішення автора, внесення погодженої зміни й повторна перевірка.

## Початок роботи в новому чаті

Новий чат потрібно відкривати в корені репозиторію. Достатній початковий запит:

```text
Продовжуємо редагування докторської дисертації. Прочитай AGENTS.md,
memory/README.md і memory/MEMORY.md та застосуй проєктні навички.
Знайди наданий фрагмент у title/, перевір його в контексті й спочатку
запропонуй редакцію. Не створюй нових наукових положень і не заповнюй
прогалини припущеннями. Не змінюй файл до мого явного підтвердження.
```

## Збирання PDF

Windows:

```powershell
cd title
.\build.ps1
```

macOS або Linux:

```bash
cd title
sh ./build.sh
```

Обидва сценарії створюють `title/dissertation_reviewed.pdf`. Якщо Tectonic відсутній, під час першого запуску він автоматично завантажується до ігнорованого Git каталогу `_tools/tectonic/`.

## Подальші узгоджені етапи

1. Послідовно опрацювати розділи дисертації з урахуванням локального контексту та чинної пам’яті.
2. Перевірити джерельну опору центральних тверджень і межі наукових висновків.
3. Виконати наскрізну перевірку термінології, позначень, формул, рисунків, таблиць і висновків між розділами.
4. Зібрати контрольний PDF і провести змістове та візуальне рецензування.
5. Занести зауваження рецензентів до пам’яті, отримати рішення автора та внести лише погоджені зміни.
6. Додати до Git текст, пам’ять і супровідні правила одним узгодженим набором змін, щоб інші учасники отримали той самий робочий контекст.
