## Статус і межі

Джерело: `../../../../suport_info/ontology_robocha_prgrama.json`.

Статус: незавершена чернетка спеціального JSON-каталогу, не OWL/RDF/JSON-LD і не зовнішній норматив. Джерело містить два окремі синтаксично коректні JSON-об’єкти: базовий блок на рядках 1–136 і профіль вибіркової дисципліни на рядках 138–229. Як один JSON-документ файл невалідний через другий корінь на рядку 138.

Модель описує переважно титульну й адміністративну частину робочої програми: реквізити, класифікацію дисципліни, навчальне навантаження, авторів і погодження. Вона не визначає змістові модулі, результати навчання, методи викладання, критерії оцінювання, літературу чи повну структуру документа.

## Модель застосування

Використовувати підтверджене користувачем проєктне трактування:

1. `base` — перший блок; застосовувати до всіх дисциплін.
2. `mandatory` — застосовувати `base`.
3. `elective` — застосовувати `base + explicit elective overrides` із другого блоку.
4. Явне elective-перевизначення має пріоритет над відповідним базовим правилом лише для вибіркової дисципліни.
5. Відсутність поля в elective-блоці не означає його скасування.

Це робоче рішення проєкту, а не формальна семантика вихідного JSON. Якщо статус дисципліни невідомий і впливає на відповідь, уточнити його.

## Базова модель

Опис титульної сторінки на рядку 5 прямо називає її складові обов’язковими реквізитами. Тому елементи верхньорівневого переліку `містить` на рядках 7–20 трактувати як обов’язкові за цією чернеткою: реквізити університету, гриф, назву, освітню класифікацію та програму, обсяг і шифр, статус, мову, підрозділи, таблицю навантаження, підставу розроблення, авторів і погодження. Це не встановлює автоматично обов’язковість кожного вкладеного підполя або його кардинальність.

## Перевизначення для вибіркової дисципліни

Застосовувати лише для явно вибіркової дисципліни.

| Область | Explicit elective override | Рядки |
|---|---|---|
| Статус | `вибіркова` | 141–145 |
| Погодження | Не включати схвалення вченою радою факультету | 165–166, 223–225 |
| Таблиця навантаження | Джерело описує одну форму без поділу за формами здобуття освіти | 168–171 |
| Види роботи | Лекції, лабораторні, практичні/семінарські, самостійна робота | 169–171, 199–206 |
| Семестровий контроль | Один контролюючий елемент, наприклад залік; `+` позначає наявність контролю, а не його назву | 171, 208–211 |
| Гриф | Декан факультету; правий верхній кут | 173–175 |
| Підписи | Автор(и); завідувач кафедри; без підписів вченої ради | 177–180 |
| Підстава | Освітня програма відповідного рівня; стандарт вищої освіти; навчальний план | 185–192 |
| Таблиця годин | ЄКТС; академічні години разом; лекції; лабораторні; практичні/семінарські; самостійна робота; семестровий контроль | 196–211 |
| Погодження кафедрою | Засідання кафедри; номер протоколу; дата; без вченої ради | 215–225 |

Відсутність згадки про печатку не є її явною забороною. «Один семестр», «одна форма» й «один контроль» подавати як source-specific constraints із невизначеною універсальністю, а не як підтверджені зовнішні нормативи.

## Правила відповіді

1. Визначити статус дисципліни, якщо він впливає на відповідь.
2. Застосувати `base`, а для вибіркової дисципліни накласти explicit elective overrides.
3. Не вирішувати конфлікти мовчки та не трактувати мовчання як скасування.
4. Розділяти зафіксоване правило, alias, робочу інтерпретацію й невизначеність.
5. Не додавати зовнішніх нормативів або типових розділів без прямого дозволу.
6. Відсутній верхньорівневий реквізит із рядків 7–20 позначати як «обов’язковий за чернеткою, але відсутній». Інше відсутнє поле не називати помилкою, якщо його обов’язковість не визначена.
7. Під час генерації залишати placeholders замість вигаданих значень.
8. Під час валідації використовувати стани: `відповідає`, `суперечить`, `обов’язковий за чернеткою, але відсутній`, `відсутнє за невизначеної обов’язковості`, `не покрито`, `потребує уточнення`.
9. Для змістових частин повної робочої програми прямо повідомляти про межу покриття.
10. Не парсити сирий файл як один JSON-документ.
